# AzerothCore Database Backup System

This directory contains the automated database backup system for AzerothCore using Docker and cron.

## Overview

The backup system automatically creates compressed MySQL dumps of all AzerothCore databases on a scheduled basis. Backups are stored in the `/data/sql/ac-backups/` directory (bind-mounted to `/backups` in containers).

## Features

- Automated scheduled backups using cron
- Dedicated backup user with minimal required privileges
- Compressed backups (gzip) to save disk space
- Configurable backup retention (auto-cleanup of old backups)
- Customizable backup schedule via environment variables
- Support for multiple databases (auth, world, characters, playerbots)

## Files

- `backup-databases.sh` - Main backup script that performs mysqldump
- `create-backup-user.sql` - SQL template for creating the backup user
- `init-backup-user.sh` - Initialization script to create the backup user in the database
- `entrypoint.sh` - Container entrypoint that sets up cron and starts the backup service
- `crontab` - Default crontab configuration (dynamically generated by entrypoint.sh)

## Configuration

Configure the backup system using environment variables in your `.env` file:

### Backup User Credentials

```bash
BACKUP_USER=backup              # Username for backup operations (default: backup)
BACKUP_PASSWORD=backup_password # Password for backup user (default: backup_password)
```

**Important:** Change the default password in production!

### Backup Schedule

```bash
BACKUP_SCHEDULE=0 2 * * *       # Cron format (default: daily at 2:00 AM)
```

Common schedule examples:
- `0 2 * * *` - Daily at 2:00 AM (default)
- `0 */6 * * *` - Every 6 hours
- `0 0 * * 0` - Weekly on Sunday at midnight
- `0 3 1 * *` - Monthly on the 1st at 3:00 AM
- `*/30 * * * *` - Every 30 minutes

### Backup Retention

#### Daily Backups

```bash
BACKUP_RETENTION_DAYS=7         # Keep daily backups for 7 days (default: 7)
```

Set to `0` to disable automatic cleanup (not recommended).

#### Weekly Backups (Optional)

Enable weekly backups to keep long-term snapshots:

```bash
BACKUP_KEEP_WEEKLY=true                  # Enable weekly backup retention (default: false)
BACKUP_WEEKLY_RETENTION_DAYS=30          # Keep weekly backups for 30 days (default: 30, 0 = forever)
BACKUP_WEEKLY_DAY=0                      # Day of week for weekly backups (default: 0 = Sunday)
```

**How it works:**
- On the configured day (e.g., Sunday), backups are marked as "weekly" with a `-weekly` suffix
- Weekly backups are kept separately from daily backups
- Set `BACKUP_WEEKLY_RETENTION_DAYS=0` to keep weekly backups forever
- `BACKUP_WEEKLY_DAY`: 0=Sunday, 1=Monday, 2=Tuesday, 3=Wednesday, 4=Thursday, 5=Friday, 6=Saturday

**Example:** Keep daily backups for 7 days, but keep Sunday backups for 90 days:
```bash
BACKUP_RETENTION_DAYS=7
BACKUP_KEEP_WEEKLY=true
BACKUP_WEEKLY_RETENTION_DAYS=90
BACKUP_WEEKLY_DAY=0
```

### Databases to Backup

```bash
BACKUP_DATABASES=acore_auth acore_world acore_characters acore_playerbots
```

Space-separated list of databases to backup. Default includes all AzerothCore databases.

## Usage

### Starting the Backup Service

The backup service starts automatically with Docker Compose:

```bash
docker compose up -d ac-backup-cron
```

Or start all services including backups:

```bash
docker compose up -d
```

### Viewing Backup Logs

View container startup logs:

```bash
docker logs ac-backup-cron
```

Or follow container logs in real-time:

```bash
docker logs -f ac-backup-cron
```

View detailed backup execution logs (stored in `env/dist/logs/backup.log`):

```bash
tail -f env/dist/logs/backup.log
```

Or from within the container:

```bash
docker exec ac-backup-cron tail -f /azerothcore/logs/backup.log
```

### Manual Backup

To run a backup manually without waiting for the scheduled time:

```bash
docker exec ac-backup-cron /scripts/backup-databases.sh
```

**Windows PowerShell:**
```powershell
.\scripts\local\win\backup-now.ps1
```

### Manual Cleanup

To manually run the cleanup process and remove old backups:

```bash
docker exec ac-backup-cron /scripts/cleanup-backups.sh
```

**Windows PowerShell:**
```powershell
.\scripts\local\win\cleanup-backups.ps1
```

This will:
- Remove daily backups older than `BACKUP_RETENTION_DAYS`
- Remove weekly backups older than `BACKUP_WEEKLY_RETENTION_DAYS` (if enabled)
- Display cleanup statistics

### Listing Backups

```bash
ls -lh /data/sql/ac-backups/
```

Or from within the container:

```bash
docker exec ac-backup-cron ls -lh /backups/
```

### Restoring from Backup

To restore a database from a backup:

```bash
# Extract and restore a specific database
gunzip < /data/sql/ac-backups/acore_world_20250130_020001.sql.gz | \
  docker exec -i ac-database mysql -uroot -p<password> acore_world
```

Replace `<password>` with your root password from `DOCKER_DB_ROOT_PASSWORD`.

## Backup File Naming

Backup files are named with the following format:

```
<database_name>_<timestamp>.sql.gz
```

Example: `acore_world_20250130_020001.sql.gz`
- Database: `acore_world`
- Date: 2025-01-30
- Time: 02:00:01

## Security Considerations

1. **Backup User Privileges**: The backup user has only the minimum required privileges for backups:
   - `SELECT` - Read data
   - `LOCK TABLES` - Ensure consistent backups
   - `SHOW VIEW` - Dump views
   - `RELOAD` - Certain backup operations
   - `REPLICATION CLIENT` - For master-data option
   - `EVENT` - Dump events
   - `TRIGGER` - Dump triggers

2. **Password Security**: Always change the default backup password in production environments.

3. **Backup Storage**: Ensure `/data/sql/ac-backups/` has appropriate permissions and is on a volume with sufficient space.

## Troubleshooting

### Backups Not Running

1. Check if the cron service is running:
   ```bash
   docker exec ac-backup-cron ps aux | grep cron
   ```

2. Verify the crontab is loaded:
   ```bash
   docker exec ac-backup-cron crontab -l
   ```

3. Check backup logs:
   ```bash
   tail -f env/dist/logs/backup.log
   ```

   Or from within the container:
   ```bash
   docker exec ac-backup-cron cat /azerothcore/logs/backup.log
   ```

### Insufficient Privileges Error

If you see privilege errors, the backup user may not have been created correctly. Recreate it:

```bash
docker exec ac-backup-cron /scripts/init-backup-user.sh
```

### Disk Space Issues

Monitor disk usage of the backup directory:

```bash
du -sh /data/sql/ac-backups/
```

Reduce `BACKUP_RETENTION_DAYS` or increase available disk space if needed.

### Changing the Schedule

After modifying `BACKUP_SCHEDULE` in `.env`, restart the backup service:

```bash
docker compose restart ac-backup-cron
```

## Maintenance

### Cleaning Up Old Backups Manually

If you need to manually clean up backups:

```bash
# Delete backups older than 30 days
find /data/sql/ac-backups/ -name "*.sql.gz" -type f -mtime +30 -delete
```

### Verifying Backup Integrity

Periodically verify that backups are valid:

```bash
# Test that the backup can be extracted
gunzip -t /data/sql/ac-backups/acore_world_*.sql.gz
```
